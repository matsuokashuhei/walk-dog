# 開発セッションの振り返り

発見事項をスキル解決策に変換することで、将来のユーザー修正を排除する。「もっと注意する」のようなソフトな助言は完全な成果とはみなさない。

## 実行タイミング

- セッションのプルリクエストが `main` にマージされた後（ユーザーがマージを依頼し完了した場合を含む）
- ユーザーが明示的にセッションの振り返りを依頼した時

## ワークフロー

1. アクティブセッションディレクトリとマージされた PR から証拠を収集する：
   - `transcript.md` およびその他のセッション記録
   - エージェントを修正した PR レビュースレッドとイシューコメント
   - 設計、命名、スコープ、プロセスを方向付けたユーザーメッセージ
   - 最初の設計が判断を省略したために存在した延期フォローアップ
2. 各発見事項を以下としてリストする：
   - **トリガー** — エージェントが行ったまたは提示した内容
   - **見逃した動作** — ユーザーが指摘しなければならなかった内容
   - **望ましい動作** — 修正なしで次回発生すべき内容
3. すべての発見事項に対して**スキルアクション**のみを提案する：
   - `.agents/skills/<name>/SKILL.md` に新しいスキルを作成し、`.agents/skill-library/` を再生成する
   - 既存スキルの指定セクションを更新
   - `run-dev-session` に `REQUIRED SUB-SKILL` フックを追加または強化
4. `docs/logs/<timestamp>-<slug>/retrospective.md` に発見事項、提案スキルパスとセクション意図、ステータス `awaiting-approval` または `ready-to-implement` を記述する。トランスクリプト成果物リストに追加する。
5. スキル提案をユーザーに提示する。明示的な承認後にのみスキル変更を実装する。
6. 承認されたスキル編集が反映された後（またはユーザーが実装を辞退し振り返り記録のみが残った後）、振り返りを結果で更新し、`syncing-session-artifacts` でセッション成果物を同期する。その同期後、次の許可アクションは `open-follow-up-pr` となる。
7. フォローアップ PR で振り返り（および承認されたスキル編集）を `main` に反映させる：
   - `origin/main` からの新しいブランチを推奨（元のセッションブランチは既に削除されている可能性がある）
   - `retrospective.md`、更新されたトランスクリプトと成果物リスト、承認されたスキルファイルの変更をコミットする
   - プッシュし、`main` に対するフォローアップ PR を開く
8. フォローアップ PR がマージされたとき（振り返りのみ、または承認されたスキル編集を含む）、次の許可アクションは `done` となる。

## 発見事項の品質基準

- すべての発見事項が少なくとも 1 つのスキル作成または更新にマッピングされる
- ソフトな助言のみとして発見事項を残さない
- 修正を防いだであろう最小のスキル変更を優先する
- 複数の発見事項が 1 つの根本原因を共有する場合、1 つのスキル変更でカバーできる。その旨を明示する

## スコープ外

- エージェントプロセスに関係ないプロダクト機能開発
- Crit レビューツーリング
- プルリクエストのマージ（マージはこのスキルの前または外で行われる）

## 完了チェック

振り返りを終了する前に：

- すべての発見事項にスキルアクションがある
- `retrospective.md` が存在し、トランスクリプト成果物リストに記載されている
- 提案が提示され、実装はユーザー承認を待った
- スキル編集がまだ承認待ちか既に適用されているかをステータスが反映している
- `main` へのフォローアップ PR パスが定義されているか、既に開始されている（`open-follow-up-pr` → `done`）
