# Hono API のテスト

API テストを変更する前に、最新の公式 Hono テストドキュメントを読むこと。ランタイムは Node.js のみ。

## 必要なドキュメントレビュー

1. テストを作成または変更する前に <https://hono.dev/docs/guides/testing> を開く。
2. 型付きテストヘルパーを使用する場合に <https://hono.dev/docs/helpers/testing> を読む。
3. 読んだドキュメントの URL とテストの判断を、アクティブセッションログ、設計、またはプルリクエストの説明に記録する。

## プロジェクトのデフォルト

- アプリケーションファクトリーをインポートし、Node.js リスナーを起動せずに `app.request` を呼び出す。
- 公開コントラクトをカバーする：`GET /health`、`GET /openapi.json`、リクエスト ID 動作、共有 JSON エラーレスポンス。
- JSON ボディテストでは、バリデーターが期待する場合は `Content-Type: application/json` を設定する。
- ステータス、ペイロードフィールド（該当する場合は `code`、`message`、`requestId`、`retryable`）、必要なヘッダーをアサートする。

## ワークフロー

| フェーズ | 提供内容 |
| --- | --- |
| ドキュメントレビュー | 読んだテスト手法と公式 Hono ドキュメント |
| 設計 | テスト対象のリクエスト、期待ステータス、ペイロード、ヘッダー |
| 実装 | レビュー済みドキュメントに従ったファクトリーアプリに対するテスト |
| 検証 | 変更したテストケースのテストコマンド結果 |

## よくある判断

| リクエスト | 実装前に読むもの | 記録 |
| --- | --- | --- |
| 新しいコントラクトテスト | Testing guide | リクエスト、期待ステータスとボディ |
| 型付きテストクライアント | Testing helper | ヘルパー使用法とアサーション |
| バリデーション失敗ケース | Testing guide と validation docs | 無効ペイロードとエラーコントラクト |
| OpenAPI ドキュメントアサーション | Testing guide と OpenAPI skill | `/openapi.json` に存在するパス、スキーマ、またはセキュリティ |
| 認証ルートケース | Testing guide とプロジェクト認証コントラクト | トークン設定と 401/200 期待値 |

## 完了チェック

テストの変更が完了したと報告する前に、レビューしたドキュメント、変更したテスト、検証コマンド結果を提供すること。
