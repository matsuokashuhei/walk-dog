  2. OTP要求成功後、/verifyへ遷移する。

01.5Walk画面Ready → Starting → Recording → Completed / Failed
Ready→Starting→Recording→CompletedFailed

Ready

Startは、同じOwnerのDogを1頭以上選択し、foreground・background位置情報を許可し、Active Walkの開始条件を満たした場合に有効。不足条件は理由を表示する。

Starting

開始要求中を表示する。API開始失敗時はReadyへ戻り、理由を表示して手動Retryを可能にする。

Recording

  • Background中もWalkと位置情報取得・送信を継続する。
  • 現在のDog名、経過時間、距離、pace、Participant、Event操作を表示する。
  • EventはPee、Poop、Sniff、Greetから選択し、Participantを指定する。
  • Event送信失敗時は「記録に失敗しました」と表示し、同じEventを手動Retryできる。
  • Finish失敗時はRecordingを維持し、手動Retryを可能にする。

Completed / Failed

  • Finish成功時にCompletedとし、Walk Detailへ遷移する。
  • 再送・同期不能、位置情報許可取り消し、API上のActive Walk消失時はFailedとして破棄する。
  • History・Goal progress・ContributionはCompleted Walkをデータソースとする。

Active Walkの優先

起動、Sign In、Foreground復帰、タブ移動時はAPI上のActive Walkを照会する。recordingはRecording、startingはStartingとして復元する。

Active Walk中のSign Outは確認ダイアログを表示する。承諾時はActive WalkをFailedとして破棄してSign Outし、キャンセル時はWalkとSessionを維持する。

Walk画面は地図・数値・Dog別Event操作を一枚の記録シェルにまとめ、状態に応じて主操作を切り替える。

01.6履歴・Owner・SettingsCompleted / offset / preferences / legal
  • HistoryはCompleted Walkを開始日時の新しい順で表示する。
  • 初回20件を取得し、下端到達時にoffset方式で追加する。同時刻はWalk ID降順とする。
  • Owner Historyでは複数Dog Walkを1件として表示する。Dog Detailでは対象DogがParticipantのWalkを表示する。
  • TrackPointが0件でもCompleted Walkは距離0として表示する。
  • Eventが0件の場合は「記録されたEventはありません」を表示する。
  • Owner表示名は必須、前後空白除去、空文字不可、最大100文字。Avatarは任意。
  • 言語は日本語・英語、対応外の端末言語は英語。単位初期値はkmでmileへ変更可能。
  • AppearanceはLight、Dark、Systemの3択で初期値System。通知は初期ONでOFFへ変更可能。
  • SettingsにはSign Out、利用規約、プライバシーポリシー、アプリ情報を配置する。
  • タイムゾーンはアプリ内変更なし。未設定時は端末タイムゾーンを使用し、週間集計は月曜開始。

02 / API specification

API仕様

外部APIの契約、リクエスト、Response、状態遷移、冪等性を確認する。

Client boundary

  • Base URLは/v1。
  • 認証が必要なAPIはAuthorization: Bearer <access_token>。
  • モバイルは認証付きAPIを利用する。

Wire format

  • 日時はISO 8601 UTC。
  • JSONフィールドはcamelCase。
  • 成功時はリソースまたは処理結果。

Identity

  • Sign Up成功時にOwnerを作成。
  • 認証確認APIはusername、session、codeを受け付ける。
  • sessionは認証確認を継続するopaqueな値。

Derived values

  • Goal Progressは期間ごとに1つ。
  • ContributionはOwnerまたは指定Dog。
  • 複数Dog Walkのdurationは各Dogへ全量加算。

02.7状態・エラー契約失敗時の端末状態
Start

失敗時はreadyを表示し、理由と手動Retryを提供する。

Finish

失敗時はrecordingを維持し、同じFinishを再試行できる。

Active消失

API上のActive Walkが消えた場合、端末側のWalkをfailedとして破棄。

401 / Refresh失敗

Active WalkをFailedとして破棄し、再認証へ進む。

Sign Out

Active Walk中は確認。discardActiveWalk=trueなら破棄してSign Out。

TrackPoint

取得時刻・位置・順序を保持して自動再送。

05 / ubiquitous language

用語

画面・API・論理モデルで同じ意味を指すための辞書。

Owner
アプリ上でDogを管理し、Walkを開始する利用者。
Dog
Ownerが管理する散歩対象。同一Owner内ではNameを重複させない。
Goal Revision
Dogに一定期間適用されるGoalの履歴。変更時に新しいRevisionを追加する。
Walk
1回の散歩。1頭以上のParticipantを持つ。
Active Walk
Ownerあたり1件まで存在する未完了Walk。
Participant
Walkに参加するDog。
TrackPoint
Walk中に採用された緯度・経度の記録。
Event
Walk中にParticipantに起きたPee、Poop、Sniff、Greet。
Contribution
Completed Walkから算出するOwner単位の集計。
Completed
履歴、Goal progress、Contributionの対象になる唯一のWalk状態。
