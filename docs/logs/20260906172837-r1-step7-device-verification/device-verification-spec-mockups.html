実機検証 画面契約

起動・Foreground 復帰・タブ移動で Active Walk を API と照合し、Background 中も位置取得と送信を継続する。 照合の正本は GET /v1/walks/active である。

  • 入力: 認証済みセッション、位置情報 foreground + background 許可、ローカル Compose API（同一 LAN）
  • 照合タイミング: アプリ起動後の Walk 表示、AppState active 復帰、Walk タブ focus
  • 成功状態: API に Active Walk がある → Recording。無い → Ready（または Failed からの復帰操作）
  • Active 消失: Recording 中に GET /v1/walks/active が 204 → Failed
  • Background: 10 秒間隔の TrackPoint 取得・永続キュー送信が継続する
  • 通信復帰: Recording 中に未送信 TrackPoint を自動再送する（回数上限なし）

この縦切りで使っている既存 API

  • GET /v1/walks/active — Active Walk または 204。照合の正本。
  • POST /v1/walks/:walkId/track-points — Background / Foreground の位置送信。失敗時は端末キュー保持。
  • DELETE /v1/walks/:walkId — 位置許可喪失時など、Recording を Failed にするときに使用（既存契約）。

新規 HTTP 契約は追加しない。振る舞い変更がある場合のみ既存契約を更新する。

受け入れ環境

iPhone 実機 + 同一 LAN 上のローカル Compose API（EXPO_PUBLIC_API_BASE_URL は端末から到達可能なホスト。127.0.0.1 ではない）。 VPS API 実機検証は後続。
